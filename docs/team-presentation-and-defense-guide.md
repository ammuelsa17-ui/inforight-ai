# InfoRight AI — Team Presentation & Judge Defense Guide

> **Version 2.0 Notice**: Version 2.0 sections in this guide are presentation requirements. They must not be used in the final demonstration until the corresponding routes, source data, tests, and deployed workflows are verified.

## 1. Project Identity & Positioning Statement
> **InfoRight AI** directly addresses Problem Statement 3 (*AI for Civic and Legal Empowerment*) through a focused, end-to-end RTI drafting workflow. It converts ordinary municipal road complaints into 3–5 objective requests for certified copies of existing government records, provides a deterministically constructed authority recommendation, and generates an editable RTI application draft.

---

## 2. Technical Decision Rationale (How to Explain Code to Judges)

| Technical Question | Engineered Explanation |
| :--- | :--- |
| **Why is applicant data kept client-side?** | To enforce a strict privacy boundary by design. Personal applicant fields (`applicantName`, `applicantAddress`, `signature`) are never sent in API requests or prompts. They are merged into the document template locally in browser state only during preview rendering and PDF/print export. |
| **Why is eligibility matching rule-based?** | To prevent AI hallucination of government benefits or rules. Scheme matching evaluates citizen inputs against deterministic rules (referencing **myScheme** framework). Gemini explains matching reasons but does not decide eligibility. |
| **Why are URLs not generated by Gemini?** | Prevents Gemini from generating source URLs; links are resolved from the curated registry and manually verified before submission (**e-Jagriti**, **SAMADHAN 2.0**, **myScheme**). |
| **How does citation allowlisting work?** | Incoming `sourceIds` are intersected server-side against an official allowlist. If an invalid or non-allowlisted ID is detected, it is stripped or activates fallback mode. |
| **What activates fallback mode?** | Fallback mode is triggered deterministically on Gemini API timeout (>8s), HTTP errors, malformed JSON, invalid citations, subjective question generation, or unredactable PII detection. |
| **How is controlled failure simulated during demos?** | Failure simulation relies on server-side flag `ENABLE_DEMO_FAILURE=true` coupled with `simulateFailure: true` in the request body. Server logic verifies `process.env.ENABLE_DEMO_FAILURE === "true" && request.simulateFailure === true`. Disconnecting the browser network only triggers a client fetch error, not a server fallback. |
| **How is state-dependent tenancy handled?** | Rent control and tenant protection laws vary by state (e.g., Tamil Nadu Regulation of Rights and Responsibilities of Landlords and Tenants Act). The Rights Navigator displays explicit state-jurisdiction warnings and links to official state rent authorities. |

## 3. How to Answer "Did You Use AI Tools During Development?"

If judges ask whether AI tools were used during development, respond with:

> *"We used AI-assisted development to accelerate implementation, but the team designed the architecture, froze the contracts, curated and verified official sources, reviewed every generated change, implemented deterministic safety controls, and tested the complete deployed workflows. Gemini is also an intentional runtime component of the product, restricted strictly to specific drafting tasks."*

## 4. Live Demo Script (10-Step Sequence)

1. **Original Issue Entry**: Enter an original civic road complaint into `/ask`.
2. **Suitability & Triage Check**: Demonstrate how the system flags subjective questions (*"why was my road not repaired?"*) and explains conversion to requests for certified copies of existing records.
3. **Guided Form Inputs**: Complete guided location and road detail questions.
4. **Verified Source Records**: Display verified official source records and verification badges.
5. **Generate Application Draft**: Click Generate to produce the formatted RTI draft with 3–5 record requests.
6. **Network Privacy Inspection**: Open Developer Tools → Network tab and confirm `applicantName` and `applicantAddress` are absent from the JSON request payload.
7. **Controlled Server Failure Simulation**: Trigger controlled server failure simulation (`ENABLE_DEMO_FAILURE=true` and `simulateFailure: true`).
8. **Server Fallback Verification**: Show the server-generated fallback response with predetermined record requests.
9. **Edit and Copy**: Edit subject/questions inline and copy to clipboard.
10. **Print / PDF Export**: Click **Print / Save as PDF** to show clean `@media print` layout hiding navbar, background gradients, and action buttons.
